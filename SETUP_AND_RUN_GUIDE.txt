================================================================================
                    AI-SQL-OPTIMIZER-NODE : FULL SETUP & RUN GUIDE
================================================================================

This document provides a comprehensive, step-by-step guide to setting up,
configuring, running, and troubleshooting the AI SQL Optimizer project.

--------------------------------------------------------------------------------
1. PROJECT OVERVIEW & ARCHITECTURE
--------------------------------------------------------------------------------
The AI SQL Optimizer is a full-stack application designed to analyze, optimize,
and convert SQL queries using artificial intelligence (Groq Llama 3.3 70B model)
and Redis caching for high-performance response times.

Architecture Components:
  - Frontend: React 19 + Vite + Axios + Lucide Icons (Runs on http://localhost:5173)
  - Backend:  Node.js + Fastify + OpenAI SDK (configured for Groq API)
              (Runs on http://localhost:5000)
  - Caching:  Redis Server (Runs on 127.0.0.1:6379)
  - AI Engine: Groq API (llama-3.3-70b-versatile model via OpenAI-compatible SDK)

--------------------------------------------------------------------------------
2. SYSTEM PREREQUISITES
--------------------------------------------------------------------------------
Before proceeding, ensure you have the following installed on your system:

  1) Node.js (v18.x or v20.x+ LTS Recommended) & npm (v9.x+)
     - Verify installation in your terminal:
         node -v
         npm -v

  2) Redis Server (v6.x or v7.x+)
     - Required for caching query optimization results.
     - See "STEP 1: REDIS SETUP" below for OS-specific installation instructions.

  3) Groq API Key (Free)
     - Required for AI query optimization and conversion.
     - Get your key from: https://console.groq.com/keys
     - Sign up / log in -> Click "Create API Key" -> Copy the key (starts with "gsk_...").

3. STEP-BY-STEP SETUP INSTRUCTIONS
--------------------------------------------------------------------------------

----------------------------------------
STEP 1: Set Up & Start Redis Server
----------------------------------------
The backend requires a running Redis server at redis://127.0.0.1:6379 by default.

  [Option A: Windows - Using Docker (Recommended)]
  If you have Docker Desktop installed:
    1. Open PowerShell or Command Prompt.
    2. Run the following command to start a Redis container:
         docker run -d --name redis-server -p 6379:6379 redis:latest
    3. Verify Redis is running:
         docker ps

  [Option B: Windows - Using WSL 2 (Windows Subsystem for Linux)]
    1. Open your Ubuntu/WSL terminal.
    2. Install Redis:
         sudo apt update && sudo apt install redis-server -y
    3. Start Redis service:
         sudo service redis-server start
    4. Verify Redis is running:
         redis-cli ping
       (It should respond with: PONG)

  [Option C: macOS - Using Homebrew]
    1. Install Redis:
         brew install redis
    2. Start Redis service:
         brew services start redis
    3. Verify Redis is running:
         redis-cli ping

  [Option D: Linux (Ubuntu/Debian)]
    1. Install Redis:
         sudo apt update && sudo apt install redis-server -y
    2. Start and enable Redis:
         sudo systemctl start redis-server
         sudo systemctl enable redis-server

  [Option E: Cloud Redis (No local installation needed)]
    - You can use a free cloud Redis instance (e.g., Upstash or Redis Cloud).
    - Copy the connection URL (e.g., redis://default:password@host:port) and set it
      as REDIS_URL in your backend .env file in Step 2.


----------------------------------------
STEP 2: Set Up & Configure the Backend
----------------------------------------
1. Open a terminal and navigate to the "backend" directory:
     cd d:\aman\AI-SQL-OPTIMIZER-NODE-main\backend
     (or on Unix/Mac: cd /path/to/AI-SQL-OPTIMIZER-NODE-main/backend)

2. Install all backend dependencies:
     npm install

   This installs:
     - fastify (Web framework)
     - @fastify/cors & cors (Cross-Origin Resource Sharing)
     - dotenv (Environment variable loader)
     - ioredis (Redis client)
     - openai (OpenAI/Groq AI SDK client)

3. Configure Environment Variables:
   Ensure a file named ".env" exists inside the "backend" folder with the
   following configuration:

     PORT=5000
     GROQ_API_KEY=your_actual_groq_api_key_here
     REDIS_URL=redis://127.0.0.1:6379

   * NOTE: Replace "your_actual_groq_api_key_here" with your valid key from Groq
     (e.g., gsk_AbC123XyZ...). Do NOT use quotes around the key.


----------------------------------------
STEP 3: Set Up & Configure the Frontend
----------------------------------------
1. Open a new terminal and navigate to the "frontend" directory:
     cd d:\aman\AI-SQL-OPTIMIZER-NODE-main\frontend

2. Install all frontend dependencies:
     npm install

   This installs:
     - react & react-dom (React 19)
     - vite (Development server and bundler)
     - axios (HTTP client)
     - lucide-react (Icons)
     - react-syntax-highlighter (SQL code highlighting)

3. Verify Backend API Connection URL:
   - By default, the frontend is configured to communicate with the backend at:
       http://localhost:5000/api/sql/optimize
   - This setting is defined in: frontend/src/App.jsx (line 8: const API_URL).
   - No changes are needed unless your backend is running on a different port.

5. USING THE AI SQL OPTIMIZER IN YOUR BROWSER
--------------------------------------------------------------------------------
1. Open your web browser and navigate to:
     http://localhost:5173/

2. In the chat interface:
   - Type or paste an SQL query into the input box.
     Example:
       SELECT * FROM orders o LEFT JOIN users u ON o.user_id = u.id WHERE u.status = 'active';
   - Choose a target conversion format (e.g., "sql", "prisma", "typeorm", "mongodb").
   - Click the Send (paperclip/arrow) button.

3. Understanding the Response:
   - Optimized Query: Rewritten, highly performant version of your SQL query.
   - Indexes: Recommended database index definitions to speed up query execution.
   - Issues: Identified performance bottlenecks in your original query.
   - Explain Summary: Explanation of query execution plan improvements.
   - Converted Query: Equivalent query in your chosen target format (e.g., Prisma ORM).

6. EXAMPLE UNOPTIMIZED SQL QUERIES FOR TESTING
--------------------------------------------------------------------------------
Below is a curated set of unoptimized, poorly written SQL queries representing
common performance anti-patterns. You can copy and paste any of these examples
into the AI SQL Optimizer chat box to see how it rewrites them, suggests indexes,
and explains the performance improvements!

  [Example 1: N+1 Subquery in SELECT (Correlated Subquery Bottleneck)]
  - Why it is unoptimized: Executes multiple dependent subqueries per row instead
    of using a single LEFT JOIN with aggregation.
  - Test Query:
      SELECT 
        u.id, 
        u.name, 
        (SELECT COUNT(*) FROM orders o WHERE o.user_id = u.id) AS total_orders,
        (SELECT MAX(created_at) FROM orders o WHERE o.user_id = u.id) AS last_order_date
      FROM users u
      WHERE u.status = 'active';

  [Example 2: Using SELECT * with Leading Wildcards (Full Table Scan)]
  - Why it is unoptimized: SELECT * retrieves unused columns; leading wildcards
    ('%...') bypass B-tree indexes and force a full table scan.
  - Test Query:
      SELECT * 
      FROM products p
      WHERE p.name LIKE '%laptop%' 
         OR p.description LIKE '%gaming%' 
      ORDER BY p.created_at DESC;

  [Example 3: Function on Indexed Column in WHERE Clause (Non-SARGable Query)]
  - Why it is unoptimized: Wrapping an indexed date column in SQL functions
    (YEAR(), MONTH()) prevents index usage. Should compare against a date range.
  - Test Query:
      SELECT user_id, amount, created_at
      FROM transactions
      WHERE YEAR(created_at) = 2025 AND MONTH(created_at) = 7;

  [Example 4: Redundant DISTINCT with IN Subquery & Implicit Comma Join]
  - Why it is unoptimized: Uses outdated comma joins, redundant DISTINCT for
    deduplication, and an inefficient IN subquery instead of EXISTS or INNER JOIN.
  - Test Query:
      SELECT DISTINCT c.id, c.first_name, c.last_name, c.email
      FROM customers c, orders o
      WHERE c.id = o.customer_id
        AND c.id IN (SELECT customer_id FROM payments WHERE amount > 500);

  [Example 5: Filtering Rows in HAVING Instead of WHERE]
  - Why it is unoptimized: Filtering non-aggregate columns (status) inside HAVING
    wastes CPU/memory by grouping unnecessary rows first.
  - Test Query:
      SELECT department_id, COUNT(*) as employee_count, AVG(salary) as avg_salary
      FROM employees
      GROUP BY department_id
      HAVING status = 'full_time' AND employee_count > 10;

  [Example 6: Implicit Type Conversion / Type Casting in Filter]
  - Why it is unoptimized: Comparing a VARCHAR column (customer_phone) to an
    integer literal forces implicit type conversion on every row, disabling indexes.
  - Test Query:
      SELECT order_id, customer_id, total_amount
      FROM orders
      WHERE customer_phone = 9876543210;

  [Example 7: Unindexed JOIN with Subquery Inefficiency]
  - Why it is unoptimized: Joins derived tables without indexes and calculates
    aggregates multiple times across non-indexed foreign keys.
  - Test Query:
      SELECT e.id, e.name, d.department_name
      FROM employees e
      INNER JOIN (
        SELECT id, department_name FROM departments WHERE active = 1
      ) d ON e.dept_id = d.id
      WHERE e.salary > (SELECT AVG(salary) FROM employees);

7. HOW CACHING WORKS (REDIS MD5 CACHE)
--------------------------------------------------------------------------------
- When a query is submitted, the backend generates an MD5 hash key combining:
    MD5(query + target)
- If an identical query and target exist in Redis, the backend immediately
  returns the cached result with the flag:
    "source": "cache"
- If it is not cached, the backend invokes the Groq AI Llama 3.3 70B model,
  stores the successful result in Redis for 3600 seconds (1 hour), and returns:
    "source": "ai"

8. TROUBLESHOOTING & COMMON ISSUES
--------------------------------------------------------------------------------

  [Issue 1] Error: connect ECONNREFUSED 127.0.0.1:6379 in Backend logs
  - Cause: Redis server is not running or not accessible on port 6379.
  - Solution:
      * Start Redis via Docker: docker start redis-server
      * Or start Redis on WSL/Linux: sudo service redis-server start
      * Or verify REDIS_URL in backend/.env points to your correct Redis instance.

  [Issue 2] 401 Unauthorized / "AI request failed" from Groq API
  - Cause: Missing, invalid, or expired GROQ_API_KEY in backend/.env.
  - Solution:
      * Open backend/.env and ensure GROQ_API_KEY is set to a valid key from
        https://console.groq.com/keys.
      * Ensure there are no quotes or trailing spaces around the key.
      * Restart the backend server after modifying .env.

  [Issue 3] CORS Error or "Failed to connect to backend" in Browser Console
  - Cause: Backend server is not running on port 5000.
  - Solution:
      * Check Terminal 2 to ensure "Server running on port 5000" is displayed.
      * If port 5000 is occupied by another process, stop that process or change
        PORT=5000 in backend/.env and update API_URL in frontend/src/App.jsx.

  [Issue 4] Port 5000 or Port 5173 Already in Use
  - Solution (Windows PowerShell):
      * Find process ID using port 5000:
          netstat -ano | findstr :5000
      * Terminate the process by PID:
          taskkill /PID <PID_NUMBER> /F
  - Solution (Mac/Linux):
      * Kill process on port 5000:
          npx kill-port 5000
